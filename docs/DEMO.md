# ForgeFlow v0.2 五分钟演示

## 演示前

启动项目，打开生产排产工作台。首轮草案会根据实际台账自动计算，尚未扣减库存或下发。初始工厂为 6 笔订单、3 类产品、6 台设备。全部数据为合成数据。

## 演示路径

1. **看计划**：查看首屏准交率、延期风险与甘特图，切换设备/订单视图，悬停查看工序。
2. **改真实输入**：进入订单管理，选择待排订单，修改数量、交期或优先级，保存。回到排产页，旧草案显示数据已变化；点击“重算待排订单”。
3. **看变更影响**：重算以当前草案为对比基线，展示原/新完工时间。也可以展开排产范围，仅选择部分订单或开启硬交期。
4. **验证缺料**：在物料库存把某物料数量调低，重新排产，显示缺口并阻止审批。补回库存后重算恢复。
5. **验证停机**：在尚无工单下发时，进入设备日历，录入一个额外停机区间。重算后相关工序避开该区间。已下发后日历锁定，当前不支持在制重排。
6. **审批闭环**：在计划审批勾选确认并批准，打开生产工单。查看库存被扣减、订单标为已下发、设备时段被占用。重复批准不会重复扣料。
7. **版本保护**：保留两个同版本草案，其中一个下发后，另一个不能再下发。再次排产只允许选择剩余待排订单。

## 可以据实介绍

我构建了一个制造业生产协同原型，使用合成的订单、工艺、设备日历和库存作为输入，通过 LangGraph 编排齐套检查、CP-SAT 排程与人工审批。与固定演示不同，订单和资源数据可编辑并持久化。审批时使用版本检查和数据库事务，统一更新物料、订单、资源占用和工单；后续排程会避开已下发任务。测试覆盖业务约束、故障恢复、版本竞争与页面表单操作。

大模型接入目前为可选的场景工具选择接口；主工作台核查逻辑是确定性程序。未实现向量 RAG、真实故障预测或真实 MES 接入，不能把本原型描述成企业已上线项目。
